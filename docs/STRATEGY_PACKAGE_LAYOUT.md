# 策略源码与构建物目录约定（设计阶段）

> 状态：**目录与职责的设计约定，尚未实现策略加载或执行**。本文件记录 2026-11-23 确认的方向，不表示仓库已经提供这些目录、Strategy Runner 或策略管理 API。现行实现请以 [当前架构](ARCHITECTURE.md) 和代码为准。

## 目标

新增策略应先放入与 `data/` 平级的**源码目录**，经独立构建后进入另一个与 `data/` 平级的**构建物目录**，再由运行组件启动。策略源码、构建物与运行中的实例相互分离；后续 API 只需调用已经验证的本地安装、构建和启动能力。

首要目标是完成「一个新策略文件夹进入系统 → 编译 → 执行 → 验证可停止」的端到端链路，**暂不设计 API 细节**。

## 目标目录布局

以下为**建议采用的目标布局**，不是当前存在的文件清单：

```text
seealpha-engine/
├── engine/                       # 引擎源码与现有 Rust 组件
├── data/                         # 行情、Catalog 及其他数据（现有目录）
├── strategies/                   # 编译前的策略源码
│   ├── mean_reversion/
│   │   ├── strategy.toml         # 策略入口、运行要求等声明（拟定）
│   │   ├── Cargo.toml            # Rust 策略的构建配置
│   │   └── src/
│   ├── trend_following/
│   │   └── ...
│   └── market_making/
│       └── ...
├── strategy_dist/                # 编译/打包完成的策略构建物
│   ├── mean_reversion/
│   │   └── 1.0.0/
│   │       ├── strategy-runner   # 示例：可独立执行的 Rust 构建物
│   │       └── manifest.json    # 构建物元信息（拟定）
│   ├── trend_following/
│   └── market_making/
└── Cargo.toml                    # 现有主 Cargo workspace
```

`strategies/`、`strategy_dist/` 与 `data/` **处于同一层级**。示例策略名、版本号、文件名和 Manifest 格式仅用来解释布局，尚未定为可执行协议。

| 目录 / 组件 | 作用 | 边界 |
| --- | --- | --- |
| `engine/` | Engine 核心源码、行情与交易基础组件 | 不因增加一个具体策略就复制策略逻辑或重复实现 NautilusTrader |
| `data/` | 行情数据及既有 Catalog / 数据状态 | 策略构建不修改历史行情或绕过数据就绪约束 |
| `strategies/` | 存储原始策略项目、策略代码及构建配置 | **源码目录**，不直接当作可执行发行目录 |
| `strategy_dist/` | 存储已构建、已校验的可运行策略包；按照策略和版本隔离 | **构建物目录**，运行时使用指定的不可变版本，不在此修改源码 |
| **Strategy Runner（待实现）** | 识别构建物类型，准备受控运行环境并启动/停止策略；对接 NautilusTrader 原生生命周期 | 不重写 NautilusTrader 的策略回调、订单引擎或 OMS |

## 从新文件夹到运行的目标链路

1. **放入源码**：将一个完整策略项目放进 `strategies/<strategy_name>/`。
2. **识别与校验**：读取策略声明，确定语言、构建方式、NautilusTrader 版本和入口；检查配置有效性。
3. **独立构建**：编译/打包策略，构建成功后才发布到 `strategy_dist/<strategy_name>/<version>/`。失败不得覆盖已发布版本。
4. **按版本启动**：Runner 选择指定的构建物启动独立运行环境；Rust 策略可用独立可执行程序的形式接入 NautilusTrader，而非要求主 Engine 动态链接任意 Rust 源码。
5. **NautilusTrader 执行**：由 NautilusTrader 原生节点注册策略，管理行情事件、策略回调和生命周期。SeeAlpha 不为此创建另一套通用策略框架。
6. **验证及停止**：首先在合成/离线数据环境验证策略启动、行情回调、停止、异常退出及重启后的状态判断；实盘下单与真实账户接线另行验收。

## 必须遵守的规则

- **源代码与构建物分离**：修改 `strategies/` 不会悄悄替换正在运行的 `strategy_dist/` 版本；构建通过不等于运行已验证。
- **运行不依赖源码目录**：已部署的策略实例依赖构建物和必要的运行环境，而不是运行时读取或编译原始源码。
- **版本隔离与可追溯**：构建物按策略和版本独立保存；后续需定义校验摘要、依赖/平台兼容性和启动实例对应的版本记录。
- **策略彼此隔离**：策略进程异常不得直接终止 Engine 或其他策略；共享账户的风控、订单归属与恢复仍须单独设计和验证。
- **不限制策略算法**：均值回归、趋势追随、网格、做市和多标的策略均可使用该目录约定；不要求所有策略输出相同类型的信号。
- **不绑定单一语言**：首期优先验证 NautilusTrader Rust 策略；将来 `strategy_dist/` 可容纳 Python 包及其运行环境或其他 Runner 支持的构建物，而非仅限 Rust 可执行文件。
- **不隐式开放实盘能力**：构建/启动成功不得自动授权真实下单；账户状态、订单去重、真实成交证据和多腿策略风控必须满足独立安全门禁。
- **运行与发布解耦**：新增策略的目标是无需重新编译或重发主 Engine；具体 Runner、隔离方式、运行协议及部署策略须通过后续原型验证。

## 首个验收目标

在不修改主 Engine 策略业务代码的情况下，加入一个新的策略源码文件夹，完成构建、发行、启动，并通过离线行情验证其 NautilusTrader 回调与停止行为；随后换用第二个不同的策略重复流程。**做到这一步之后再设计对应 API。**

## 当前实现边界

截至 2026-11-23，主 HTTP Engine **尚无通用策略运行器或策略加载 API**；原 EMA 示例及相关策略路由已退役。独立 Nautilus Rust 工程位于 `engine/pipeline/sources/shared/nautilus/`，不等同于已可运行用户策略的宿主。本文仅记录已确定的文件夹结构与职责，不恢复历史 Python Engine、不修改当前 Cargo workspace，不触碰数据库、真实账户或生产部署。
